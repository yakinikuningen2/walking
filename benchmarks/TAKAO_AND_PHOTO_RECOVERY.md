# 高尾山口駅の重複と写真のタイムアウト（2026-11-15）

## 高尾山口駅

実際のPhoton応答（検索語「高尾山口駅」、上限15件）は9件でした。その中に以下の別表現・別施設があります。

- 駅舎：[OSM way 180390778](https://www.openstreetmap.org/way/180390778)、`building=train_station`、名称「高尾山口駅」。
- 駅：[OSM node 6003241794](https://www.openstreetmap.org/node/6003241794)、`railway=station`、名称「高尾山口」。
- バス停：[OSM node 2204440499](https://www.openstreetmap.org/node/2204440499)、`highway=bus_stop`、名称「高尾山口駅」。
- 線路上の停車位置：`railway=stop`の2件。

従来は駅舎を駅カテゴリに分類せず、さらに駅舎と駅の住所がそれぞれ「甲州街道」「西氷川橋」で矛盾扱いになっていました。

`building=train_station`を駅として分類し、駅名・駅カテゴリに加えて、駅舎の範囲内かつ100m以内、または範囲不明なら40m以内にある駅ノードと照合します。番地のある住所や行政区分・郵便番号・Wikidataの矛盾は引き続き保留します。条件を満たす駅舎／駅に限り、接する道路の名称が異なっていても統合します。特定の駅名・IDによる分岐はありません。

施設名検索では、親駅が候補にあり名前と位置が一致する停車位置・ホームは別の散歩先として表示しません。明示的な駅入口や、親駅が確認できない候補は保持します。

この実応答は9件から6件の表示となり、駅舎と駅は1件、同名のバス停は「高尾山口駅（バス停）」と表示します。信号・駐輪場等の別地点は残します。バス停は駅そのものと統合せず、種類を明示します。

## 写真

以前は途中のAPI問い合わせが1回タイムアウトすると、残っている取得方法を試さず終了しました。手動再取得でも成功済みの照合API応答まで使わずに取り直すため、同じ処理を繰り返す場合がありました。また、問い合わせ回数上限を時間切れと同じコードで返していました。

- 途中の通信失敗・タイムアウト後も、残りの取得方法を既存の総時間・回数上限内で試します。同一の失敗した問い合わせをその1回の処理内で再送しません。
- 記事の画像が取得できなくても、検証済みWikidataの画像や施設専用Commonsカテゴリ等が使えれば採用します。施設照合・座標・権利の確認は省略しません。
- 全候補を確認できなければ、エラーを「写真なし」として保存しません。429・503の取得先制限では代替問い合わせを継続せず、既存の60秒待機を守ります。
- 回数上限は`PhotoLimit`として時間切れと分離します。
- タイムアウト・通信失敗・回数上限後の「写真を再取得」は、地点の失敗結果を使わず、成功済みの照合API応答だけを期限内で再利用します。「写真なし」からの手動再取得や画像自体の読み込み失敗は従来どおり新しい情報を確認します。
- 同名のバス停に、駅の記事／Wikidataの写真を目的地そのものの写真として誤採用しない確認も追加しました。周辺写真は従来どおり「周辺の写真」と区別します。

同時取得2件、外部API問い合わせ最大8回／総時間18秒目安、クライアント22秒、共有メタデータ10分／96件／6MiBの既存上限を維持します。無制限な自動再試行・新しいAPI・ライブラリは追加していません。取得先全体が応答しない場合のタイムアウトを保証してなくす変更ではありません。
