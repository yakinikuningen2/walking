# walking

場所を検索し、行った場所を地図に記録する散歩アプリです。

## 使い方

1. 下記のコマンドでPythonサーバーを起動してから、VS Code の Live Server でルートの `index.html` を開きます。既存のLive Serverのアドレスを使えば、保存済みの歩く速さ・訪問記録をそのまま使えます。Pythonサーバーだけで使う場合は `http://127.0.0.1:8000/` を開くこともできます。
2. 初回は地図の上に「歩く速さ」の設定を重ねて表示します。速さ（ゆっくり：時速3 km／ふつう：時速4 km／はやめ：時速5.5 km）を選び、「保存」を押します。次回からは保存した設定で地図を直接開きます。バーはいつでも操作でき、動かすと自動で「数値で指定」に切り替わります。時速2.5〜6.5 kmを0.1刻みで調整でき、選んだ数値は「数値で指定」の右側に表示します（例：4.2 km/h）。キーボードの左右キーでも0.1ずつ調整できます。以前保存した数値が新しい範囲を外れている場合は、2.5または6.5に調整して復元します。地図右下の「歩く速さ」からいつでも変更でき、そのときも背景の地図を表示したままにします。案内中は所要時間を含めてルートを計算し直します。
3. 地図の左端にある「場所を登録」の取っ手を右に引っ張るかクリックしてパネルを開き、場所の名前や住所を入力して虫眼鏡を押すか Enter キーで検索します。候補を選ぶと候補一覧を閉じ、場所の登録欄を表示します。
4. 場所の名前・訪問日・メモを入力し、「保存」を押します。
5. 保存した場所を一覧から選ぶと地図に表示できます。編集・削除・直前の削除の取り消しもできます。

プロジェクトのフォルダで次のコマンドを実行します。追加パッケージは `requests` だけです。

```powershell
.\.venv\Scripts\python.exe app.py
```

ターミナルを開いたまま使います。終了は Ctrl+C です。PythonサーバーはこのPCの `127.0.0.1:8000` で動き、Live Serverからの地図情報の検索を中継します。起動していない場合は、従来どおりブラウザから検索APIへ接続します。ポートを変更する場合は `app.py --port 8001` のように指定し、表示されたPythonサーバーのURLから開いてください。

`app.py` の更新後は、起動中のPythonサーバーを Ctrl+C で止めてから起動し直してください。同じポートへの二重起動はエラーにして、古いコードと新しいコードが同時に応答することを防いでいます。

速さの設定中は、どの項目を選んだあとでも矢印キーはスライダーだけを操作します。右・上で0.1 km/h増やし、左・下で0.1 km/h減らします。範囲は2.5〜6.5 km/hです。

検索で見つからない場所は、地図をクリックして直接登録できます。

登録パネルを開くと、「目的地を探す」が右へ移動します。閉じると元の位置に戻ります。狭い画面では、操作できる幅を保って画面内に収まる位置へ移動します。

「歩く速さ」も地図上のパネルで開き、表示中に地図・検索・場所登録・現在地などを操作できます。「閉じる」で閉じても未保存の入力は保持します。パネルが重なる場合は選んだ画面を手前に表示します。「目的地を探す」はほかの画面を選んでも開いたままにし、入力・候補・検索中の通信を保持します。
保存した場所にメモがある場合は、地図のポイントの上に常時表示します。メモの編集・削除は地図上の表示にも反映されます。
パネルは取っ手を左に引っ張る、取っ手をクリックする、または Escape キーで閉じられます。地図は常に画面いっぱいに表示し、パネルを左から重ねて引き出します。入力途中の内容は開き直しても残ります。マウス・タッチ操作に対応しています。
通常のホイール操作は地図の移動、Ctrl＋ホイールやタッチパッドのピンチは拡大・縮小です。

## 現在地

アプリを開くと現在地の取得を開始します。ブラウザの位置情報へのアクセスを許可すると、現在地を青い丸で表示して地図の中心を移動します。取得中に地図を操作したり目的地を指定した場合は、表示位置を保ちます。薄い青の円は位置情報の誤差の範囲です。

地図右下に「現在地」と「歩く速さ」を縦に並べて表示します。「現在地」を押すと、縮尺を変えずに現在地へ戻ります。最新の位置も取得します。起動時の取得が終わっていない場合は、その結果を使って移動します。取得中・取得完了のメッセージは表示しません。

- HTTPS、または Live Server の `http://localhost:ポート番号`・`http://127.0.0.1:ポート番号` で開いてください。HTTP の LAN アドレスでは位置情報を取得できません。
- ブラウザと端末の位置情報の許可が必要です。許可拒否・取得失敗・タイムアウトは画面に表示します。
- 起動時・「現在地」を押したとき・現在地をスタートにした徒歩ルートの表示・更新時に取得します。現在地を訪問記録として保存したり、自動で追跡したりしません。

## スタート地点

「目的地を探す」を開き、画面上部の「スタート地点」の「検索」を押すと、名前・住所の検索欄を表示します。初期値は現在地です。場所の名前・住所を入力し、虫眼鏡か Enter キーで検索して候補を選ぶと、紫の丸でスタート地点を表示します。変更後も検索画面は開いたままです。別の場所を指定した場合だけ、検索欄の下に「現在地に戻す」を表示します。「現在地」など表示中のスタート地点名を押すと、スタート地点の検索欄を閉じます。右下の「現在地」ボタンは地図を現在地へ戻す操作で、選んだスタート地点は変更しません。

ルート案内と「条件で探す」は、このスタート地点を使います。検索した場所を選んだ場合は、位置情報を許可していなくても使えます。スタート地点を変えると案内中のルートを更新し、条件検索の通信と現在の候補を解除します。過去の候補は検索履歴に残ります。指定はページを開いている間だけ保持し、再読み込み時は現在地に戻ります。

「現在地」「検索」と同じ行にある「地図で指定」から、直接地図をタップ・クリックしてスタート地点を決められます。紫のマーカーを置いて検索画面へ戻り、その地点をルート案内と条件検索の出発点に使います。地図の縮尺と表示位置は保ちます。「戻る」または Escape キーで指定をやめられます。通常の地図操作で地点を選んだ場合も、登録欄の「スタート地点に指定」から設定できます。訪問記録を保存する必要はありません。

## 目的地

地図の「目的地を探す」ボタンを押すと、中央に検索画面が開きます。上部の検索欄に名前・住所を入力し、虫眼鏡を押すか Enter キーで検索できます。その下に徒歩時間や雰囲気などの条件を並べて表示します。タブ切り替えや折りたたみはありません。開いたまま地図や現在地なども操作できます。「閉じる」で閉じても入力・候補・スクロール位置は保持します。

「名前・住所で検索」は地名・施設名・住所が分かる場所を探す機能です。「条件から探す」は徒歩時間・場所の種類・雰囲気などから行き先の候補を提案します。両者は見出しと区切り線で分け、それぞれの操作の下に結果を表示します。条件検索は「条件に合う場所を探す」から実行し、画面上部の経過時間にも「条件検索」と明記します。

候補を押すと、その場所を直接目的地に指定して検索画面を閉じます。目的地の指定時は地図の縮尺を変えず、表示の中心だけ移動します。

「場所を検索」の候補や地図上の場所を選び、「目的地に指定」を押すこともできます。登録地点は一覧や地図上の詳細表示からも指定できます。場所の名前や訪問記録を保存する前でも指定できます。目的地は赤い丸と「地図マーカーのアイコン素材4.png」のアイコンを合わせて表示します。

目的地を指定すると、地図右下に目的地の情報と「目的地を解除」ボタンが表示されます。「目的地を探す」から続けて別の目的地を検索できます。別の場所を指定すると目的地が切り替わります。入力中の訪問記録は保持します。目的地は現在のページ内で保持し、再読み込みすると解除されます。

## 条件から目的地を探す

「目的地を探す」の名前検索欄の下に、条件を並べて表示します。開いている間も地図の移動・拡大縮小、名前での目的地検索、現在地などを操作できます。条件検索中に名前検索をしても、条件検索は続きます。経過時間は画面上部に表示します。

片道の徒歩時間を「時間」と「分」で入力すると、指定時間の30分前〜30分後の範囲から候補を探します。たとえば2時間なら徒歩1時間30分〜2時間30分、6時間30分なら徒歩6時間〜7時間の場所が対象です。下限が0分を下回る場合は0分にします。5分以上で指定でき、時間の上限はありません。入力欄の下にも対象の時間帯を表示します。最初は「散歩先」で、山・森・川辺・湖畔・海辺・街並み・集落・公園・景色のよい場所から探します。施設を目的にしなくても使え、山だけ・森だけなどに絞ることもできます。種類の選択肢は「散歩先」「すべて」を先頭に、自然、街歩き・観光、飲食、買い物の順にまとめています。駅は条件検索の対象に含めません。

雰囲気は「都会寄り」「田舎寄り」「自然が多い」から選べます。「山」「海辺」「田舎 森」のように希望欄へ短い言葉を並べても使えます。「山」などで希望した種類が近場にない場合は、概算の徒歩時間内で検索範囲を広げます。「散歩先」で「田舎 カフェ」と指定した場合は、希望したカフェも検索対象に加えます。雰囲気・希望した種類・名前の一致を候補の優先順位に反映します。「田舎寄り」は周辺確認を通った場所に絞り、都会や未確認の候補で件数を埋めません。「都会寄り」「自然が多い」は従来どおり希望に近い場所を優先します。選択した場所の種類と、概算での徒歩時間を条件にします。希望欄は対応する短い言葉と名前・説明の一致を使い、任意の自然文全体を解釈する機能ではありません。

「標高が高め」にチェックすると、徒歩時間・種類・雰囲気に合う取得済みの候補から最大24件の標高を比較し、高い順に最大5件表示します。「高台」「高原」「標高が高い」と希望欄に入力しても使えます。海抜300mなどの固定の下限は設けず、取得できた候補の中で比較します。地図に記載された標高がなければ、既存の [Valhallaの標高API](https://valhalla.github.io/valhalla/api/elevation/api-reference/) で候補の座標をまとめて調べます。森や湖などの範囲は中心や山頂ではなく、目的地として使う輪郭上の座標で調べます。結果には「標高 約120 m」のように目安を表示し、標高不明の候補はこの条件では表示しません。標高データは10分間再利用します。標高条件と結果の数値も検索履歴に残ります。

「田舎寄り」は、都会らしさが少ない場所も含むアプリ内の目安です。[田畑](https://wiki.openstreetmap.org/wiki/Tag:landuse%3Dfarmland)や[集落](https://wiki.openstreetmap.org/wiki/Tag:place%3Dhamlet)が近くにあることを必須にせず、周辺情報を取得したうえで、中心市街地や店の密集などがなければ候補に含めます。田畑・集落は800m以内、山・森は少し離れた2km以内まで考慮し、それらがある候補を優先します。都会らしさは目的地から400m以内で判定し、都市の中心・大型商業施設・工業地、店や対象施設が6件以上ある場所、商業地と住宅地が重なって店などが3件以上ある場所を除外します。小さな商業区画や住宅地だけでは除外しません。駅以外の場所にも同じ基準を使い、地域名のブラックリストは使いません。

周辺情報の通信が終わるまでは「田舎寄り」の候補を表示せず、通信に失敗した場所も表示しません。正常に取得できた場合は、田畑・山林・集落の登録がなくても、都会らしさが少ない候補を表示できます。候補なしと通信失敗は短いメッセージで区別し、検索中の取得・確認件数や判定基準の説明文は画面に表示しません。経過時間・かかった時間と対象の徒歩時間帯は引き続き表示します。希望欄に「田舎」と入力した場合にも同じ基準を使います。地図の登録状況による差があるため、行政上の区分や人口密度を使った正式な田舎の定義ではありません。

保存した歩行速度と現在地から候補を探します。時間帯の下限が0分の場合は近場から探し、候補が足りなければ範囲を広げます。それ以外は対象の時間帯全体を最初から検索し、同じ範囲の取得を繰り返さないようにします。候補は常に指定時間の30分前〜30分後に収まるものに絞ります。

候補を選んで地図に戻ったあとも、検索条件・候補一覧・スクロール位置を保持します。「条件で探す」を開き直すと、再検索せずに別の候補と比較できます。直近10件の検索条件と候補一覧はブラウザ内に保存し、「検索履歴」から過去の検索も呼び戻せます。再読み込み後は、最新の検索結果を復元します。履歴の候補には「検索時の目安」と表示し、現在地や歩く速さが変わっていても目的地として選べます。ルート案内は実際の現在地から行います。

公園・山頂など、地点の座標を使う種類は検索先でも対象の距離帯に絞ってから取得します。近場の場所が取得枠を埋め、6時間〜7時間などの遠い場所が取得前に漏れることを防ぎます。種類ごとに取得枠を分けます。通常は矩形の範囲検索と座標からの距離条件を併用し、取得後に球面距離で時間帯を再確認します。極地・日付変更線付近や半径100km超では距離条件をブラウザ側だけで確認します。森・湖などの範囲は中心点だけでは除外せず、輪郭を取得して到着地点の時間を確認します。[Overpass QL](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL)の出力上限はブラウザで絞る前に適用されるため、地点は時間帯を先に絞る必要があります。

「歩ける時間」は候補の検索範囲に使う時間で、検索処理の待ち時間とは別です。検索画面上部と検索中のボタンに「12秒」のように経過秒数を1秒ごとに表示します。上部の秒数はスクロールしても確認できます。検索終了・中止後は「かかった時間：5.2秒」のように小数1桁で結果を残し、次の検索で0秒から数え直します。検索全体を30秒で打ち切る制限はありません。最初の検索先が4秒で応答しない場合はもう一方にも同じ検索を送り、先に返った結果を採用して不要になったブラウザの通信を中止します。両方が混雑・タイムアウトの場合は30〜60秒程度の間隔を空けて再試行します。各通信は最大60秒待ちます。応答が戻り次第候補を表示します。「中止」で検索を止めた場合も、表示済みの候補は選べます。画面を閉じると通信を止めますが、候補一覧は残します。条件を変更すると現在の一覧を消し、以前の候補は検索履歴に残します。該当する場所がない場合や検索条件が無効な場合は、その結果を表示して終了します。

候補ごとの経路計算は行わず、直線距離を1.3倍して一般的な回り道を見込み、設定した歩行速度で所要時間の目安を出します。概算で表示中の時間帯に収まる候補を、希望への近さ・所要時間の順に最大5件表示します。取得できた候補は残りの周辺情報の確認や追加検索を待たずに選べます。候補を押すと目的地に指定でき、地図の縮尺は変えません。「徒歩ルートを表示」を押したときに実際の経路と所要時間を計算します。滞在時間と帰路は含みません。

最初は地点名・座標などの軽い情報だけを取得します。森・川・湖・海岸などの輪郭が必要な場所は、候補が足りないときに地図IDで最大12件ずつ追加取得します。全件の細かい輪郭を最初から取得しないことで通信量を減らします。川・湖の中心や、未確認の森林の中心を代わりの目的地として表示することはありません。取得済みの輪郭も10分間再利用します。[Overpassの公式説明](https://dev.overpass-api.de/overpass-doc/en/full_data/bbox.html)でも、大きな関係データの形状を出力すると通信量が増えるため、必要な範囲に絞る方法が説明されています。

- 雰囲気は最大8候補ずつ（「田舎寄り」は4候補ずつ）、目的地の座標から周辺情報をまとめて取得して推定します。「田舎寄り」は4候補の確認が終わるたびに表示を更新し、後続の通信に失敗しても表示済みの候補は残します。店・施設は400m、「田舎寄り」の土地情報などは800m、山・森だけは2kmまで調べます。矩形検索で取得し、判定時には実際の距離で絞ります。候補ごとに土地など80件・店16件・施設16件・離れた山や森40件の取得枠を分け、混雑した場所だけで他の候補の取得枠が埋まることを防ぎます。大きな森・湖の形状全体を起点に検索しないため、離れた街の情報を混ぜずに確認できます。「田舎寄り」は周辺情報を取得できた候補が5件そろうか対象がなくなるまで次の候補も調べます。取得した周辺情報は10分間再利用します。各候補の雰囲気表示は目安です。
- 「無料」と表示するのは地図に無料と明記され、条件付き料金が設定されていない場所だけです。設備は場所自体の地図情報に記載されている場合に表示し、周辺設備だけの追加検索や優先条件は設けていません。未登録の料金・設備を推測して表示しません。営業時間や混雑、設備までの通行可否は判定しません。
- 候補の時間は道路や入口を調べる前の概算です。川・線路・私有地などにより大きく回り道する場合や、徒歩で到達できない場合があります。実際のルート案内で確認できます。
- [山](https://wiki.openstreetmap.org/wiki/Tag:natural%3Dpeak)は山頂の地図上の点を使います。[森・林](https://wiki.openstreetmap.org/wiki/Tag:natural%3Dwood)は地図上の森林・林の範囲を使い、川・湖・海岸も候補に含めます。範囲のデータがある場所は現在地に近い輪郭上の点を使い、川や湖の中心は目的地にしません。輪郭は検索範囲付近だけ取得し、種類ごとに取得枠を分けて、特定の種類だけで候補が埋まるのを防ぎます。輪郭上の点が実際の入口・遊歩道であるかは未確認です。山の標高差・登山道の難しさは概算時間に反映していません。
- 現在地・検索範囲、候補の座標や輪郭を調べる地図IDを [Overpass / Private.coffee](https://overpass.private.coffee/) と [Overpass API](https://overpass-api.de/) に送ります。直前に応答した検索先を優先し、応答がない場合や失敗時にもう一方を利用します。Pythonサーバーの起動中は同じ内容を `requests` でPOST送信します。Live Serverから直接検索する場合もフォーム形式のPOSTを使い、長い検索式をURLに含めません。送信先は従来と同じです。ブラウザから通信を中止しても、中継サーバー側の通信は完了またはタイムアウトまで続く場合があります。条件検索中に経路計算は行いません。「標高が高め」を使う場合は、標高が未登録の候補の座標だけを既存の Valhalla の標高APIへ送ります。ルート案内では Valhalla に現在地・目的地・経由地の座標と歩行速度を送信します。標高取得と経路計算は1秒以上の間隔を空けます。検索履歴には検索条件・検索時の出発地点・候補をブラウザ内だけに保存し、履歴一覧を外部に送信する処理はありません。
- 施設・周辺情報は最大10分、ページを開いている間だけキャッシュします。直前に取得できた検索先を優先し、失敗した検索先への再接続は30秒以上空けます。雰囲気の追加情報も4秒で応答しなければもう一方へ問い合わせ、各通信は最大15秒待ちます。追加情報を取得できなくても確認済みの候補は残しますが、「田舎寄り」の未確認候補は表示しません。外部サービスが停止している間は、待っても候補を取得できないことがあります。「中止」でいつでも止められます。

## 徒歩ルート案内

目的地を指定し「徒歩ルートを表示」を押すと、まず選んだスタート地点からの基本のルートを表示します。追加の候補は見つかった場合だけ提示し、種類ごとの固定枠・検索中の枠・見つからなかった枠は表示しません。見つかったルートは地図上に色分けして同時に表示し、候補一覧にも対応する色の線を添えます。候補を押すと道順が切り替わり、ほかのルートも表示したままになります。候補が1本だけなら候補一覧も表示せず、そのまま道順を使えます。切り替え時の自動拡大・移動は行いません。

- **基本のルート**：歩行者用の道路・歩道を使うルートです。必ずしも距離が最短になるとは限りません。
- **坂道少なめ**：勾配・階段をなるべく避けて計算し、基本のルートと違う道になる場合に提示します。坂や階段を完全に避ける保証はありません。
- **自然を楽しむ**：公園・自然保護区の歩道を経由できる場合の候補です。私有地・立入禁止・有料指定のある場所を除いて探します。
- **コンビニが多い道**：周辺のコンビニを検索し、最大2か所の店舗付近を経由する候補を比較します。ルートから直線距離で約60m以内にある店舗を数え、基本のルートより件数が多く、2件以上ある候補だけを提示します。同名で約20m以内の重複データはまとめます。件数も画面に表示します。比較した候補の中から選ぶもので、周辺すべての道について件数が最大になることを保証するものではありません。

同じ道を通る候補や、大きく遠回りする候補は追加しません。候補ごとに距離と所要時間を表示します。設定した歩行速度を経路サービスに渡して所要時間を計算します。「道順」を開くと日本語の案内を確認できます。道路名は地図データの表記を使用します。

スタート地点や目的地の切り替えでルートを更新します。「ルートを更新」では選んだスタート地点から計算し直します。現在地を選んでいる場合は最新の位置を取得します。「案内を終了」で線と道順を消します。目的地を解除すると案内も終了します。ルート表示による自動拡大は行いません。

- 経路計算には [Valhalla / FOSSGIS](https://valhalla.openstreetmap.de/) の歩行者用モードを利用します。現在地・目的地・経由地の座標と歩行速度を送信します。[歩行者向けの勾配・速度設定](https://valhalla.github.io/valhalla/api/route/api-reference/#pedestrian-costing-options)を利用しています。
- 公園内の歩道・コンビニの検索には [Overpass / Private.coffee](https://overpass.private.coffee/) を使い、現在地と目的地の中間地点・検索範囲を送信します。周辺データは最大10分、ページを開いている間だけキャッシュします。店舗数は取得できた地図データの範囲の目安で、営業時間・店の入口へのアクセス・現地の通行状況は保証しません。
- 経路リクエストは最低1秒間隔です。追加候補の取得に失敗しても基本のルートを使えます。目的地の変更や案内終了時は古いリクエストを中止します。経路を取得できない地点を直線で結ぶことはありません。
- 所要時間は推定です。移動中の位置情報は自動追跡せず、更新ボタンで再取得します。音声案内はありません。

## 保存と検索

- 記録はブラウザの localStorage に保存されます。端末間の同期はありません。
- 歩行速度も localStorage に保存します。訪問記録とは別のキーを使います。保存できない場合も、その画面を開いている間は選んだ速度で利用できます。
- 同じブラウザ・同じオリジン（プロトコル、ホスト、ポート）で再度開くと、記録を復元します。
- ブラウザのサイトデータを消すと記録も消えます。
- 地図と検索にはインターネット接続が必要です。検索できない場合も地図から手動で登録できます。
- 検索は [Photon](https://github.com/komoot/photon) の公開デモAPIを利用します。虫眼鏡または入力欄での Enter キーで検索します。入力中の自動検索は行わず、日本語変換を確定する Enter キーでは検索しません。結果をセッション内でキャッシュし、連続リクエストは1秒以上間隔を空けます。入力を変えると前の検索を中止し、候補とメッセージを消します。
- 検索候補は最大15件です。国名は国コードから日本語に変換し、住所は現地語で取得して国内の地名を日本語で表示します。現在の公開APIは日本語指定に対応していないため、日本国外の都市名・道路名などは現地語表記が残る場合があります。
- Photon のデモAPIは適度なリクエスト数での利用向けで、稼働保証はありません。多数のユーザーに公開する場合は専用の検索サーバーに変更してください。接続先は `static/js/app.js` の `SEARCH_ENDPOINT` にあります。
- 検索語は検索サービスに送信されます。訪問日・メモ・記録一覧は送信しません。
